# 快速检索与读写规则（Turbo / Windows pwsh）

## 1. 检索与读取（减少回合 & 命中白名单）

- 先定位再精读：搜内容用 `rg -n --max-columns 200 'Pattern' .`（**必带路径 `.`，正则含 `$` 必用单引号**；先用 `rg -l` 看命中分布再精确 `rg -n`）。
- 摸清结构：未确认目录或文件名时先跑 `rg --files` 或 `rg --files --iglob '*name*'`，不盲猜子目录，非必要不 `ls` 翻目录。
- 只读命令禁拼接：`rg`、`git status/diff/log/show` 等白名单只读命令**严禁**使用 `cd`、`&&`、`;`、`|` 或重定向拼接，必须单条独立并在同轮并行发出。
- 一次读够：用 `read_file` 读命中点附近 150–200 行，300 行以内整份读；同文件相距 ≤200 行的片段合并读取；大文件先用 `rg -n` 搜类/函数签名定位行号再并行精读。
- 并行与去重：同一轮内并行发出互不依赖的搜索与 `read_file`；已读且未改动的内容不重读。

## 2. 命令与修改（pwsh）

- 读文件用 `read_file`，不用 `cat`/`Get-Content`；看改动用 `git diff`；`ls` 不传 Unix 参数（如 `-la`），不用 `tail`/`head` 等非原生 Unix 命令。
- 必审命令合并：互不依赖的校验/构建/测试等执行类步骤，用 `&&` 合并为一次 `run_command`；优先用工具自带精简参数控量（如 `-q`、`-n`），必要时用 `| Select-Object -Last 20` 截尾。
- 修改文件：小改动用 `edit_file`，同文件邻近多处合并为一次，独立文件同轮并行；跨 ≥5 个文件的机械替换用单次脚本批处理后再 `git diff` 核对。

## 3. 输出与收尾

- 先给结论再列要点（写清路径与符号名），不贴大段代码或复述已读代码，一般回答控制在 1,500 字以内。
- 找到答案直接收尾，不为了确认多翻文件；小任务不生成计划/总结文档。
